# Rebuild evidence

Data artifacts kept in-repo because a live decision or a running tool still needs them. A closed-round triage dump does not belong here: once its conclusion has landed in the runes and ledgers, the dump goes, since git preserves it (see `AGENTS.md`, “Note-taking and the rebuild logs”).

- `verdicts-carried-<short hash>.json` — the carried verdict master: the latest resolution of every recorded human verdict, keyed by `rebuild/tools/carry_verdicts.py` to the review surface built at commit `<short hash>`. This is the sole surviving copy of the human decisions — the per-sitting exports it is carried from are scratch — which is why it is checked in while every other verdicts file stays gitignored. After each artifact cycle, replace it with the fresh carried master the cycle writes at the repo root, renaming to the new short hash, unless `WHATNEXT.md` records a hold on the current file: a still-open decision whose only tracked evidence is that carry keeps it alive until the decision lands, and then the newest carry takes over.
