# What next

The living punch list for the Abbots Morton Spaceport rebuild — the forward-looking companion to the per-milestone plans under `rebuild/`. It records what ought to happen next, the open forks in the road, and the deferred work we have consciously parked. Keep it current: see “Keeping this file honest” at the bottom.

## The main thread — M1 rune migration

The rebuild is migrating the cursive-join engine rune by rune, validating each batch against the old shipped font via the oracle.

**Current frontier: the qsI batch is built and green, and its sitting has not been held.** The rune, the alphabet, the aliases and the gates all landed; `make verdict-ready` is the standing check, and `rebuild/M1-BATCH6-PROGRESS.md` carries the batch's recorded design overrides and the questions the sitting has to answer. Adjudicating it is what closes the batch; `glyph_data/runes/` is the roster of what has already migrated.

**Migrating a letter takes five hand-updates that nothing prompts for**, four of which fail by producing a confidently wrong number rather than an error, so do them before trusting any oracle figure: `rebuild/pipeline/baseline_subset` (refilters the oracle tables against `M1_ALPHABET`; nothing calls it), `rebuild/m1-aliases.yaml` (an entry per old compiled glyph name — for the new rune _and_ for already-migrated neighbors whose old forms only ever appear beside it), `rebuild.review.census --update`, and three hardcoded artifact counts in the rebuild suite that grow with the alphabet (`test_review_enrich`'s subset row count, `test_review_build`'s echo-group sibling count, and `test_emit`'s two `@m1_form_guard_qsDay_qsUtter` class memberships). Wiring the first into `run_m1` ahead of the oracle step is the obvious fix and is not done.

**Where the state lives, so this file need not carry it.** `make verdict-ready` — and the same status as a banner in the app — answers whether the surface, gates, and verdict store are ready: surface freshness by input fingerprint, gate greenness, verdict-store alignment, the frontier carry, blanks remaining, server. `rebuild/out/cycle_summary.json` is the last cycle’s own record (surface units and echo groups, unmatched oracle rows, each gate’s status, and the `verdicts-carried-<sha>.json` it wrote with how many verdicts rode it); the per-gate summaries under `rebuild/out/m1/` hold the rest (`conform_summary.json`, `boundary_equivalence_summary.json`, `manual_pins_summary.json`, `budget.json`, `oracle_summary.json`); the store itself is `verdicts-autosave.json`, journaled in `verdicts-journal.ndjson`, which the newest verdicts ride until the next cycle’s carry; and `make complaint-docket` clusters the open reject/neither verdicts by the rune records that decided them. Read those; don’t copy their numbers back into this file, where they go stale the next time a cycle runs.

**The standing shape of the gates**, which is what a number here would have been trying to say: the conform sweep and the boundary-equivalence sweep are exact — zero divergences, full rule and transition coverage; the Manual pins replay clean under the no-waiver gate; and the budget gate’s yellow flag is its steady state rather than a warning, because the M1 GSUB rides type-7 Extension offsets (`m1_settle` is `useExtension`). The oracle’s remaining unmatched rows are verdict-gated divergences from the old font, not failures — among them the deliberate ss03 ·Fee·Tea divergence, where the rune extends by 1 per the old derive’s stated intent and the divergence lands through verdicts with no ledger entry. The docket’s standing complaints are windows already argued and accepted, so a _fresh_ complaint is the signal. The artifact cycle lands the echo prefill and the checked-in standing approvals (`rebuild/standing-approvals.yaml`) itself after its carry+merge, so only genuinely new questions ever queue — and echo groups key on the localized ink delta, which puts unchanged flanking letters, including followers that merely slid over by an advance change, outside the grain.

**The live decisions a later batch must not re-litigate.** Each rune’s own `why:` is the authority; this is the index. ·Pea·No renders `·Pea.!half ~b~ ·No.alt` in every window: half-·Pea’s x-height exit no longer reaches ·No (a `qsNo` carve-out on the `toward:` scope), paired with the matching ·Pea carve-out in qsNo’s x-height-exit prefer, which otherwise wins the seam back before ·Day/·No/·It/·Oy/·Fee and — with only the qsPea half — turns ·Pea·No·Oy into a break rather than a low join. The accepted price is ·Pea·No·Fee and ·Pea·No·Oy, which stop after ·No instead of chaining on at the x-height. ·Fee cannot join both to and from at the x-height, and that is structural rather than policied: qsFee is the clockwise `loop` (top-entry stub, x-height exit) plus the counter-clockwise join-born `reversed-loop` (`require: [entry]`, no exits). qsFee prefers its forward x-height join over the backward one when entered from ·May/·No/·Low — except before ·Tea and ·Utter, where the approved taste keeps the backward join — paired with the matching qsFee carve-out in qsMay’s follower prefer; the engine raises E-INCOMPARABLE if either side widens without the other. qsFee’s exit row admits the qsX_qsUtter ligatures (extend-by-1 before ·Day·Utter via the lead), so ·X·Fee·Day·Utter joins. The ·Pea·May-family windows deliberately keep the un-extended baseline join and ride the may-baseline-entry-extension-dropped class instead of matching the old font’s en-ext-1.

·X·Day·Tea·Day, ·X·Day·Tea·It and ·X·No·Tea·It regroup like the old font. The ·X·Day·Tea·No windows render their third form (`·X·Day | ·Tea.!half ~b~ ·No.alt`), and ·Day·Tea·No·dot rides along because `boundary` includes the namer dot. Word-initial ·No·Utter·May joins on both sides via ·Utter.alt as a strict gain — qsUtter’s before-·May follower prefer paired with the matching carve-out in qsNo’s boundary prefer, again E-INCOMPARABLE if either widens without the other — while ·No·Utter·Day stays with the old font, restoring the plain “alt-·Utter only before ·Low or on strict gain” principle. qsDay’s yielding prefer is one unscoped record; qsNo carries the scoped baseline twin, before ·Tea·It; ·Day also yields before ·Tea·No at a run end; and full ·Tea joins ·No.alt at the baseline through qsTea’s `order: [full, half]`. Read the follower sets off the runes — they grow with every migration.

**The depth-4 fork stands as landed.** In the default config, X₀·Day·Tea·Utter·Tea·X₁ and ·Oy·Tea·Utter·Tea·X₁ render the predecessor yielded and ·Tea~·Utter joined for every baseline-enterable X₁; ·Pea/·Tea/boundary followers keep the rescue, a following ·Oy does not (·Tea·Oy ligates, so the chain’s third hop stops matching), and ss03 keeps its y5 escape and joins ·Utter on both sides. The chain grammar is depth-4 — nested `then:` chains, capped at three hops past `right` — with the cap and the table’s fourth slot derived from `model.RIGHT_WINDOW_SLOTS` and an import-time arity assert; the runes that carry such a chain are whichever prefer records nest a `then:`, and that set grows batch by batch, so read the runes rather than a list here. ·Oy takes the shape without qsDay’s `self: {entry: live}` scope, so word-initial ·Oy·Tea·Utter·Tea moves off the old font as well — the entry-liveness split was built and passed over, and the divergence stands adjudicated “either” on both arms. ·Day·Tea·No·Utter keeps the ·Day·Tea join per the recorded follower-of-·No scope; its approve-with-note is still worth setting in the app.

### Do when a gate takes too long

Not gated on a named event — these come due when a cycle step gets slow enough that acting pays off.

- **Conform-gate cost** — `gate:conform`, the exhaustive font-vs-settle sweep, runs at horizon 5 on every cycle whose conform inputs moved (`--conform-horizon` on the cycle driver, passed through to `run_m1 --conform-only`; `--skip-conform` opts out; on unchanged inputs a green record auto-skips it, like every heavy cycle stage — `--fresh` forces a full rerun). It no longer sits in the look-edit-look loop’s critical path: a `make review-cycle` pass that rebuilds anything defers it to the next pass, so the sweep’s cost lands on the converging pass rather than between an edit and seeing the letters — which is what makes the horizon lever below a question about how long a sitting waits to start, not about iteration speed. The decision tables are no longer part of what the gate spends: run_m1 serializes each configuration’s window enumeration beside its other artifacts (`table.write_windows` → `windows-<config>.tsv.gz`, stamped with `fingerprint.tables_value` over the sources the fixpoint read) and each sweep worker opens its own, so the fixpoint is paid once by the build and the gate’s remaining cost is shaping and settling. It rebuilds unconditionally when the stamp fails to match, which means the runes moved after the last build; measured against that fallback on the same code, the gate went 525 s → 309 s and its peak resident set 6.8 GB → 0.37 GB, and run_m1’s own table stage went 162 s → 66 s because the build’s workers stopped shipping a million `Transition` rows per configuration back to a parent that only ever read the rules and the reachable cells. The sweep term grows with the fifth power of the alphabet and shrinks with `--conform-horizon` — witness top-ups keep rule and transition coverage exact at any horizon; only off-corpus diff density shrinks. The past-horizon top-ups are dominated by committed-left prefixes deeper than the sweep, and they still grow with the enumeration even though building it has left the gate — the ·Tea·Day fix widened `depth3_inputs` from 3 runes to 7, and every window a third slot adds is a transition the top-up loop must see realized. The depth-4 fourth slot stays the cheap part (its inputs carry only a few thousand live-`right4` transitions per config between them, and a handful of emitted rules with a `lookahead4`), because `table.fourth_slot_filter` prunes don’t-care right4 fan-out at the source — a fourth token can only decide a window whose own-rune depth-4 chain is still unknown over the three nearer slots, so pruning the rest loses nothing. Each stream costs one shape plus one settle on a per-config warm engine (`settle_with_engine`); when the gate becomes the cycle’s long pole again, the lever is `--conform-horizon`, decided deliberately.

### Waiting on a specific migration or milestone

Each is blocked until a named event lands — a particular rune’s migration, or a named milestone close — and can’t meaningfully start before then.

- **Unresolved design flags** — the ss05 row-grain refusal coverage notes (re-check at the qsEt migration; the ss04 half went live and conform-verified with qsLow). The inexpressible `reaches_up_and_way_over` resolved-extension scope on qsMay’s x-height entry came due at qsAh and was settled there by accepting the 1px ·Ah·May attachment drift into the sitting, where it now carries approved; the alternatives weighed and rejected were a per-scope `contract: bind:` record and a per-from-atom schema extension. It recurs at qsI — the other short-reacher the old font attaches on qsMay’s stub-keeping form at x=3, against the entry row’s `pulled-back-stubless` binding — so expect the same drift there and decide whether the qsAh precedent still holds.
- **qsZoo Manual-pin flag** — when qsZoo migrates, the Manual pin `·Tea ~b~ ·May.en-ext-1 ~x~ ·Zoo` will trip the no-waiver Manual-pin gate; re-transcribe the pin or fix the runes at that point.
- **The ·Low·Oy·Tea·Oy standing approval is blocked on M1 shipping, not on picking a mechanism** — the durable home is the corpus pin the review surface already drafts for the window (`data-expect-noncanonically="·Low ~x~ ·Oy | ·Tea+Oy"`, syntax- and semantics-validated against the M1 font, no duplicate), because a pin is the one channel that fails loudly rather than silently re-queueing — the legacy shaping suite and the no-waiver Manual-pin gate both replay it. It cannot land yet: `test/test_shaping.py` replays every corpus pin against the _shipped_ Senior font, and this is exactly a window where the two engines disagree — the old cleanup over-reach drops the ·Low~·Oy join when ·Tea·Oy follows (`break, break`) while M1 keeps it (`y5, break`) — so the pin fails `make test` until M1 is the shipped engine. A census pin is not a substitute and never was: `rebuild/review-census-pins.json` is aggregate integers with no key space for a window, and its `--check` is informational anyway. The interim exposure is one window: carry is keyed on the render (`content_key`, then the ink signature), so any change to it strands the verdict, and the window’s echo group is a singleton so the prefill cannot cover it. The verdict's only tracked copy is `rebuild/evidence/verdicts-carried-fb4f7d6.json` under the superseded id `u-9148` — keep that evidence file until the pin lands, notwithstanding the usual retire-the-evidence rule. When it does land, the home decides which gates enforce it, so choose deliberately: only the three corpus HTML files are read by `collect_pin_runs`, so a pin lands in the M1 Manual-pin gate only from there — but the drafter's hardcoded `site/the-manual.html` is a transcription of Read's manual and this window is in neither it nor the extra-words list, and the corpus hosts no `data-expect-noncanonically` pins at all today, the earlier twenty having become `_assert_expect_any` tests in `test/test_calt_regressions.py`, which the M1 gate never sees.
- **Dormant `contract:` records** — the qsJai-keyed `contract:` records on qsNo/qsUtter/qsLow/qsAh and the qsZoo/qsJay-keyed ones on qsTea never fired in the migrated corpus; re-adjudicate them when qsJai/qsZoo/qsJay migrate and can actually exercise them. (·May carries no after-·Fee contract: its entry row’s `pulled-back-stubless` binding already covers every enterer.)
- **qsFee's forward-preference left scope** — the prefer covers the three newly-widened backward sources (·May/·No/·Low). When qsI/qsOut/qsOwe migrate, their backward joins into ·Fee match the old font and need no widening — but re-audit any own-prefer on a newly-migrated left family that fires with a qsFee follower and demands the opposite seam; qsMay is the only left family that has needed the paired carve-out.
- **The ·Tea·Day tight bond is per-rune and must be re-checked at every migration** — the standing taste is that a ·Tea·Day pair keeps its forward join, so nothing upstream may spend ·Tea’s one baseline slot backward (qsTea.full’s `pairings.never` makes that slot exclusive). No ·Tea→·Day seam in the migrated alphabet may lose its forward join; holding that as letters arrive takes records in two shapes, and a new rune may need either. **The ordinary shape** is the yielding prefer already idiomatic on qsDay and qsNo — `{cell: {exit: none}, over: {exit: baseline}, when: {right: {family: qsTea, then: {family: qsDay}}}}`, default `yields-to-joins`, no `why` demanded — which any newly-migrated family that can exit into ·Tea will want. **The ·Utter shape** is the `mode: absolute` twin on qsFee/qsNo/qsMay/qsUtter naming `{right: {family: qsUtter, then: {family: qsTea, then: {family: qsDay}}}}`: ·Utter’s `alternate` stance is the one place whose exit is mandatory (`require: [exit]`), so an x-height join into ·Utter forces the stranding from two positions away, and only the letter _before_ ·Utter can prevent it. That copy is needed by every family qsUtter’s x-height entry `from:` list admits — re-check that list at each migration — and `absolute` is load-bearing there, because the joining candidate outscores the yielding one on join-count and a default-mode record is a total no-op.
- **Open fork: should run-final ·Utter join backward at the x-height?** — deferred out of the ·Tea·Day fix, and worth its own sitting. Today `alternate` carries `require: [exit]`, so it is unavailable at a run end and word-final ·Utter sits on `mono` taking no backward join. Giving qsUtter a non-exiting twin stance (`alternate-stopped`: same x-height entry and `from:` list, `exits: {}`, `require: [entry]`, the withdrawn bitmap, ordered last, elevated by one own-rune prefer before ·Tea·Day) moves 647 of 11,100 swept windows for **+354 joined seams** — 322 of them run-final ·Utter gaining a backward join, 274 medial windows where ·Utter’s join hops from its right side to its left. It also does the ·Tea·Day job strictly better than what shipped: same 321/321, but it _keeps_ the upstream x-height join the `absolute` records throw away, and it retires those four records and their growth problem. The costs are 15 windows losing one join (all the same shape — a medial ·Fee stranded between two joinable neighbors) and `qsDay_qsUtter` decomposing in 15 windows, though every one still joins the seam. Only ~10 of the 647 are about ·Tea·Day at all, which is why it was parked rather than ridden in.
- **Three ·Utter-local expressions of the ·Tea·Day fix, all measured and rejected** — so nobody re-derives them. Dropping `require: [exit]` outright: 641 windows, and it decomposes the ·Day·Utter ligature. Relaxing to `require: [entry]` plus an own-rune prefer: 1,035 windows, and it loses the ·Utter·Low joins. Gating the `alternate-stopped` twin with `{stance: alternate-stopped, when: {right: {except: [{family: qsTea}]}}}` so ordinary ranking can’t reach it: 120 windows and **−65 joins**, because merely offering the stance as a candidate changes lookahead-closure upstream before the refuse fires — ·Fee flips from `reversed-loop` to `loop` across the `·X·Fee·Utter` windows and drops its backward join. The wall underneath all three: `prefer` can see two letters ahead but only breaks ties, `refuse` can suppress but is confined to the immediate right neighbor (design §3.3), so nothing ·Utter-local can say “be available here and nowhere else.” Unlocking qsTea’s `(baseline, baseline)` pairing is a fourth shape, but `unlock` demands a `feature: ssNN` and so can never be the default-config answer.
- **qsAh’s entry from-list has a recon-derived tail** — the eight unmigrated members (qsGay, qsThey, qsJai, qsYe, qsHe, qsWhy, qsRoe, qsExcite) came from an FEA sweep rather than the oracle, so re-verify each at its own migration; qsRoe is the solid one (`select.before {family: qsAh, entry_y: 0}` in today’s YAML). The caution generalizes past qsAh: an FEA sweep misses bare-carrier joins, because no substitution is emitted when the base drawing already holds the live anchor — that is how qsDay/qsOy/qsTea_qsOy were nearly left out of this list before the oracle exposed the seam-losses. Derive a from-list from oracle evidence when you can.
- **The ·Day·Tea-before-·No follower set** — qsDay’s depth-3 withdraw list (read it off `glyph_data/runes/qsDay.yaml`) mirrors where ·No.flipped engages; when more baseline-entry followers migrate (qsVie, qsRoe…), ·No.flipped will engage before them too and the list needs re-adjudication.
- **The rebuild suite’s one expected failure** — `rebuild/test_surface.py::test_real_cell_bindings_all_match` fails on a clean HEAD by design; `BASELINE_REBUILD_FAILURES` in `rebuild/tools/artifact_cycle.py` is the binding copy of the expected set, subtracted as the artifact-cycle driver’s `baseline` bucket. It trips on qsUtter’s `alternate` stance binding a bitmap to the `(x-height, baseline-withdrawn)` cell, which `require: [exit]` makes unenumerable — dead drawing until the run-final ·Utter fork above decides whether an `alternate-stopped` twin uses it, so retire the failure and the driver’s bucket together when that fork resolves. A real regression in any rebuild-suite run is a failure outside that expected set (and outside the artifact-pinned census/Manual-pin tests, which go stale after any rune edit until `run_m1` + `review.build` re-run).

## Keeping this file honest

This is a punch list of what’s _left_ — not a changelog of what happened. When work lands, edit the current-state description in place and delete the status it supersedes; never append a dated `Update (…)` paragraph. What got done — with what counts, and under which commits — is already in the git log, so this file records only the live frontier: the open forks, the next batch, and the consciously-parked follow-ups. When a landed change leaves a genuinely-open residue, record the residue as a forward bullet, not the change that produced it. The broader workflow rules — no after-the-fact reports, bounded progress files, evidence that outlives its decision — live in `AGENTS.md`’s “Note-taking and the rebuild logs” section; `AGENTS.md` points back here.
