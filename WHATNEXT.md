# What next

The living punch list for the Abbots Morton Spaceport rebuild — the forward-looking companion to the per-milestone plans under `rebuild/`. It records what ought to happen next, the open forks in the road, and the deferred work we have consciously parked. Keep it current: see “Keeping this file honest” at the bottom.

## The main thread — M1 rune migration

The rebuild is migrating the cursive-join engine rune by rune, validating each batch against the old shipped font via the oracle.

**Current frontier: the qsEight batch is built and green — the next move is the ·Eight sitting.** `make verdict-ready` reports READY with the fresh ·Eight questions among the blanks, and `rebuild/M1-BATCH15-PROGRESS.md` is the batch's scratch (the owed scaling sweep, recorded design overrides, the verification recipe); delete it when the sitting closes the batch. ·Eight arrived on the ·Awe/·Ox template with more extension traffic: its entry and exit worlds are byte-identical to theirs (the same sixteen sources and receivers, the four `*_qsUtter` ligatures included), no ligature involves it anywhere in the old font, no ledger class was needed — the one old-font wart (a single window where half-·Tea joins bare ·Eight without the entry extension, the same shape ·Awe's and ·Ox's were) is absorbed by the standing `halves-entry-extension-restored` class — and the ·Tea yielding prefer is qsJai's shape verbatim once more. What distinguishes it: the entry extend names all three x-height-exiting halves (half-·Pea's dipped exit takes the extension before ·Eight, unlike before ·Awe or ·Ox; qsHe deferred), the exit side de-rubs with a `smaller-loop` stance — ·I's pair mirrored, the bowl pulled in a column wherever the baseline exit actually joins ·Tea or ·It — in place of the old +1 extensions (qsIt left ·Eight's exit-extend and qsEight left qsTea's entry-extend; qsYe/qsHe/qsExam stay parked on the exit-extend record for their migrations to convert), and the neighbors had it heavily pre-wired — qsFee, qsTea, qsI, qsRoe, and qsPea all named qsEight from their own batches, so only the seven mechanical list arms landed. On the exit side ·Eight is ·Awe, not ·Ox — the terminal pixel arrives diagonally with no ink above it, so the declined baseline exit is dangle-blessed in `rebuild/m1-contact-allow.yaml` rather than proven `withdrawal: safe` — but one ·Ox-style corner family rode along anyway: the bowl closes one column left of ·I's loop at y4, so the batch's contact-allow additions are the four dangle blessings plus the ·Eight·I corners across the two letters' variants, every one on the baseline-proven ·Eight·I join. qsEight also joined `SS10_UNCOVERED_BY_OLD_FONT`, both sides at once — no stances in its old record, so both anchors ride the base cmap glyph and keep their ss10 joins.

**Migrating a letter takes one hand-update that nothing prompts for**: the last hardcoded artifact count in the rebuild suite — `test_review_enrich`'s subset-table row count, which at least fails as an assertion when it goes stale rather than quietly reporting a wrong number. The census re-baseline that used to sit beside it is off the list entirely: every artifact-cycle pass rewrites `rebuild/review-census-pins.json` from the census sidecar the build already emitted and prints its git diff, so the alphabet-coupled counts it carries are reviewed and accepted at commit time instead of hand-updated. The ledger's `no_verdict` set, the form-guard class membership, the doc-table row count, and the ledger-exemplar count need no hand-updates either: the suite derives them from the loaded ledger, the settle verdicts, and `LETTERS` at test time. Two earlier list members came off it for their own reasons: the subset refilter, because `run_m1` runs `baseline_subset.ensure_fresh` before anything else, so an `M1_ALPHABET` edit can no longer feed the oracle stale subset tables; and `rebuild/m1-aliases.yaml`, because `run_m1` now refuses to start while any subset-row glyph name lacks an entry, naming the missing names (an entry may map to the literal `pending` to acknowledge a name mid-migration) — the aliases still need authoring, but the build prompts for them instead of silently miscounting.

**Where the state lives, so this file need not carry it.** `make verdict-ready` — and the same status as a banner in the app — answers whether the surface, gates, and verdict store are ready: surface freshness by input fingerprint, gate greenness, verdict-store alignment, the frontier carry, blanks remaining, server. `rebuild/out/cycle_summary.json` is the last cycle’s own record (surface units and echo groups, unmatched oracle rows, each gate’s status, and the `verdicts-carried-<sha>.json` it wrote with how many verdicts rode it); the per-gate summaries under `rebuild/out/m1/` hold the rest (`conform_summary.json`, `boundary_equivalence_summary.json`, `manual_pins_summary.json`, `budget.json`, `oracle_summary.json`); the store itself is `verdicts-autosave.json`, journaled in `verdicts-journal.ndjson`, which the newest verdicts ride until the next cycle’s carry; and `make complaint-docket` clusters the open reject/neither verdicts by the rune records that decided them. Read those; don’t copy their numbers back into this file, where they go stale the next time a cycle runs.

### Do when a gate takes too long

Not gated on a named event — these come due when a cycle step gets slow enough that acting pays off. "Slow enough" is measured, not remembered: every cycle appends host-tagged per-step wall times to `rebuild/out/cycle-timings.ndjson`, and `make cycle-timings` (`ARGS='--by-step'` for per-machine medians) is where to look before pulling any lever here. The lever inventory lives in [the speed-up tracking issue](https://github.com/adiabatic/abbots-morton-spaceport/issues/7), whose sub-issues cover each cycle step.

- **Table-build cost** — the fixpoint is the kernel crate's since the cutover ([issue #48](https://github.com/adiabatic/abbots-morton-spaceport/issues/48); `bench-the-rebuild/RUST-PORT-PLAN.md` records the port and its close): one single-threaded `build-tables` process per acceptance configuration, `--kernel-threads` of them in flight, each of which enumerates its fixpoint and folds it in place, leaving this side to pack the window payload and read a head and a treaty TSV back; `make cycle-timings ARGS='--by-step'` is the cost record to consult before pulling any lever. The crate's per-configuration peak is what caps the width — `--cache-census` prints what each memo holds — and the levers not yet taken on it are recorded in the kernel-ram survey's ranking: `u32` label ids with an end-of-run rank sort, seated cells (`Settled` as a seat, seam, extension), packed rows, and a niche for `Sym` so `Option<Sym>` is four bytes, each worth a fraction of a gigabyte per configuration; a per-configuration peak near 8 GB unlocks width 3 and near 4 GB width 6, where the six-configuration enumeration becomes one wave. The fold was the other lever and it has been taken: the crate writes the settlement and treaty TSVs, the window enumeration and the digests itself, `table.py`'s fold half and the 450 MB streams are gone, and every artifact came out byte-identical across the change. The deep-slot liveness probing and the class-grain fiber derivation (issue 26) ride inside the crate — one row per outcome fiber at the deep slots, expanded back for every fold-side consumer, so the enumeration scales with the fibers the kernel can distinguish rather than the alphabet. Since issue #78 the crate is the only fixpoint: the Python twin, the harnesses that byte-compared it against the crate and `run_m1 --engine python` are gone, `run_font_conformance` fails fast on a stale enumeration instead of rebuilding one in process, and `make kernel-gate` is the crate’s own gate plus the settle-level differential rather than a second fixpoint. `bench-the-rebuild/scaling/scaling.py` still re-runs after each migration batch as the early warning, because the port moved the constant and not the exponent: if the ladder keeps steepening, work avoidance comes due regardless of language. Since issue #77 the sweep runs every rung through the crate — one kernel child per rung, the `build-tables` child a build runs, so a rung's peak RSS is that process's own — and prints the whole-ladder fit in both denominators; the binding constraint is still memory rather than wall clock (the top rung's kernel child sits within reach of the `RUST-PORT-PLAN.md` half-the-box row, where the Python arm used to sit at it), so read peak RSS off each run alongside the exponents, and hand a tripped run to the speed-up tracker rather than a letter batch.
- **Surface-build cost after the unit cache** — the review surface rebuilds incrementally (issue 20): the build stamps every unit with a content key over its input closure, persists a slim store beside the manifest, and on the next build serves every key-stable unit from the previous surface's shards, re-patching the order- and ledger-derived fields so a served fragment is byte-identical to what a from-scratch build would write — `rebuild/review/unit_cache.py`'s docstring is the contract, the served-vs-recomputed sample inside every build plus `rebuild/test_unit_cache.py` over the mini bundle are the proof. The store stamps no longer carry the after font's GSUB wiring (which a rune edit always moves, and which is why the cache had never once served before), so a rune-only edit now serves the units its letters cannot reach; any pipeline or review code edit still discards the store wholesale, and a cold build is about four minutes against two for a served one. The remaining levers, measured and recorded in the surface-build survey: streaming phase 2 into shards instead of materializing every fragment in the parent (the parent's ≈4.7 GB), slimming the machine-approved fragments (issue 21 — explain and drafts are half of every shard and largest on the shard nobody opens), the prior-fragment fetch on a served build (≈26 s of parsing the previous shards), and the served-build verification sample (≈40 s; measured, it parallelizes and must stay in the worker pool). A rune edit therefore re-enriches only the windows that could feel it, and the fraction reused grows as the alphabet does; `make review-cycle ARGS='--fresh'` (or `--fresh-unit-cache` on the build CLI) bypasses the store. The load phase no longer sits outside the cache (issue 18): the ink-duplicate merge's signatures come from the persisted ink-signature store beside the unit store, keyed at the same audit-row-plus-family grain, so a steady-state pass shapes nothing there and a rune edit re-shapes only the windows that could feel it — and within the parallel phase the comparator, enricher, oracle, and drafter share one memoized shaper per font, so each (text, config) is shaped once per worker instead of up to four times. The load phase's residual floor is parsing and keying, not shaping.
- **Conform-gate cost** — `gate:conform` is the per-edit belt since the issue-74 re-charter: the exhaustive font-vs-settle sweep at horizon 4 (`--conform-horizon` on the cycle driver, passed through to `run_m1 --conform-only`; `--skip-conform` opts out; on unchanged inputs a green record auto-skips it, like every heavy cycle stage — `--fresh` forces a full rerun), about a minute at one worker per acceptance configuration, carrying the ZWNJ-structure and split-buffer checks on every boundary-bearing text since the standalone boundary gate retired, with no witness top-ups and no coverage accounting: read-back proves per build that the font holds every planned rule, `rebuild/test_rule_witnesses.py` stays the font-free dead-rule alarm, and the sweep’s charter is HarfBuzz application semantics plus the sufficiency of the window abstraction itself. It no longer sits in the look-edit-look loop’s critical path: a `make review-cycle` pass that rebuilds anything defers it to the next pass, so the sweep’s cost lands on the converging pass rather than between an edit and seeing the letters. Settlement is memoized per distinct raw window (`conform._SettledWindowWalk`): the kernel runs once per window and every recurrence across the sweep’s texts is a dict probe, so a stream’s marginal cost is the uharfbuzz shape — the memo keys on the raw window up to the fourth slot and consults no liveness oracle (since issue #78: measured faster than the probe-normalized keying it replaced, and it keeps the sweep’s settle side independent of the crate’s enumeration), alarmed by `rebuild/test_conform.py`’s walk-equivalence sweeps, and the sweep inherits the ZWNJ/split-buffer checks within the horizon the boundary gate already proved for the same font bytes (the boundary summary carries `max_length`/`configs`/`font_sha256` exactly so `conform.proven_boundary_horizon` can decline when any of that moved). Depth lives in the periodic deep sweep now: `make conform-deep` runs the same sweep at horizon 5+ overnight or on demand, its green keyed on the emitted lookup’s behavior classes (`emit_gsub.behavior_classes`, fail-closed) plus the font-compilation code and the uharfbuzz version rather than on the runes, so it stays green across rune edits that introduce no novel rule shape, and every cycle prints whether it is current or armed. When the belt becomes the cycle’s long pole again, the lever is still `--conform-horizon`, decided deliberately — a cost knob now, not a coverage knob.

- **Validators-lane cost** — the lane holds only assertions about the live artifact that no build check makes (61 tests, about two minutes at `VALIDATORS_WORKERS`), and its long pole is the six rule-witness arms at roughly forty seconds each; the lever recorded for them is the kernel emitting each rule's shortest realizing prefix into the windows head so the build fails on a dead rule and the lane only re-settles the recorded witness (validators survey part C, P2). `built_review_surface` refuses a stale surface rather than building one, so a bare `make test-rebuild` after an edit wants a surface build first.
- **A classifier or ledger edit still costs a table rebuild** — `pipeline_code` folds every `rebuild/pipeline/*.py` and the crate into the stamp the serialized enumeration carries, so an edit to the oracle's classifier re-runs `run_m1` and the belt to produce byte-identical tables (issue #81). `run_m1 --gates-only` re-runs the Manual-pin gate and the oracle over the build on disk for a by-hand check, but records no green; the remaining piece is splitting the code closure into a table side (kernel, settle, spec, emitters) and a comparison side (conform's oracle and ledger matching, the validation shaper), mechanically checked by an import-graph test, so a comparison-side edit can skip the build honestly. The same move would let the cycle keep the review server up through a gate pass (the plumbing survey's P2): today any pass that writes the store stops it, and a sitting always writes the store.
