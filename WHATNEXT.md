# What next

The living punch list for the Abbots Morton Spaceport rebuild — the forward-looking companion to the per-milestone plans under `rebuild/`. It records what ought to happen next, the open forks in the road, and the deferred work we have consciously parked. Keep it current: see “Keeping this file honest” at the bottom.

## The main thread — M1 rune migration

The rebuild is migrating the cursive-join engine rune by rune, validating each batch against the old shipped font via the oracle.

**Current frontier: the qsThaw batch is built and awaits its sitting, and the qsGay sitting is still open.** `rebuild/M1-BATCH20-PROGRESS.md` (qsGay) and `rebuild/M1-BATCH21-PROGRESS.md` (qsThaw) are the two bounded scratch files; each records its open sitting questions, design overrides, and verification recipe, and each should be deleted when its sitting closes its batch. ·Thaw is the alphabet's first entry-only rune — fifteen lefts join its baseline entry, it joins nothing rightward until qsIng migrates, and the old after-tall stance dissolved into allowlist scoping — and it needed no new ledger class, joining `SS10_UNCOVERED_BY_OLD_FONT` on the qsOut entry-side-only precedent. `make verdict-ready` is the standing check, `glyph_data/runes/` is the roster of what has already migrated, and `make novelty-order` is the way into the blanks that remain.

**Migrating a letter takes one hand-update that nothing prompts for**: the last hardcoded artifact count in the rebuild suite — `test_review_enrich`'s subset-table row count, which at least fails as an assertion when it goes stale rather than quietly reporting a wrong number. The census re-baseline that used to sit beside it is off the list entirely: every artifact-cycle pass rewrites `rebuild/review-census-pins.json` from the census sidecar the build already emitted and prints its git diff, so the alphabet-coupled counts it carries are reviewed and accepted at commit time instead of hand-updated. The ledger's `no_verdict` set, the form-guard class membership, the doc-table row count, and the ledger-exemplar count need no hand-updates either: the suite derives them from the loaded ledger, the settle verdicts, and `LETTERS` at test time. Two earlier list members came off it for their own reasons: the subset refilter, because `run_m1` runs `baseline_subset.ensure_fresh` before anything else, so an `M1_ALPHABET` edit can no longer feed the oracle stale subset tables; and `rebuild/m1-aliases.yaml`, because `run_m1` now refuses to start while any subset-row glyph name lacks an entry, naming the missing names (an entry may map to the literal `pending` to acknowledge a name mid-migration) — the aliases still need authoring, but the build prompts for them instead of silently miscounting.

**Where the state lives:** `make verdict-ready` — and the same status as a banner in the app — answers whether the surface, gates, and verdict store are ready: surface freshness by input fingerprint, gate greenness, verdict-store alignment, the frontier carry, blanks remaining, server. `rebuild/out/cycle_summary.json` is the last cycle’s own record (surface units and echo groups, unmatched oracle rows, each gate’s status, and the `verdicts-carried-<sha>.json` it wrote with how many verdicts rode it); the per-gate summaries under `rebuild/out/m1/` hold the rest (`conform_summary.json`, `boundary_equivalence_summary.json`, `manual_pins_summary.json`, `budget.json`, `oracle_summary.json`); the store itself is `verdicts-autosave.json`, journaled in `verdicts-journal.ndjson`, which the newest verdicts ride until the next cycle’s carry; and `make complaint-docket` clusters the open reject/neither verdicts by the rune records that decided them. Read those; don’t copy their numbers back into this file, where they go stale the next time a cycle runs.

**The standing shape of the gates**, which is what a number here would have been trying to say: the conform belt is exact — zero divergences at horizon 4 — and since the standalone boundary gate retired it carries the ZWNJ-structure and split-buffer checks itself (`make conform-deep` carries them at 5+); read-back proves the font holds the planned rules and the rule-witness gate proves every rule reachable; the Manual pins replay clean under the no-waiver gate, scope included; and the budget gate’s yellow flag is its steady state rather than a warning, because the M1 GSUB rides type-7 Extension offsets (`m1_settle` is `useExtension`). The oracle’s remaining unmatched rows are verdict-gated divergences from the old font, not failures — among them the deliberate ss03 ·Fee·Tea divergence, where the rune extends by 1 per the old derive’s stated intent and the divergence lands through verdicts with no ledger entry. The docket’s standing complaints are windows already argued and accepted, so a _fresh_ complaint is the signal. The artifact cycle lands the echo prefill and the checked-in standing approvals (`rebuild/standing-approvals.yaml`) itself after its carry+merge, so only genuinely new questions ever queue — and echo groups key on the localized ink delta, which puts unchanged flanking letters, including followers that merely slid over by an advance change, outside the grain.

## Deferred and tracked follow-ups

### Doable anytime

Nothing gates these — act on any cycle, whenever it’s worth it.

- **`·Key·Utter·May` breaks before the alternate ·Utter where every other baseline-reaching left joins.** Two records manufacture that shape — a qsUtter refuse of the mono x-height exit scoped to left ·Key right ·May, plus a qsKey yielding prefer to break the resulting tie — and they exist only to hold the Manual pin at `site/the-manual.html:3985`, which entered the no-waiver Manual-pin gate's scope when ·Key migrated. [Issue #103](https://github.com/adiabatic/abbots-morton-spaceport/issues/103) is the live proposal — the normal ·Utter by default, the Manual's shape behind a stylistic set with the pinned word wrapped to switch it on — and holds the measurements and the routes, the blast radius among them: striking both records leaves `run_m1` green and the Manual-pin gate failing on that one pin alone, with nothing else in the alphabet moving.
- **The ss10 uncovered-set has pre-existing holes batch 13 measured but did not repair.** Five migrated runes whose anchors ride their base cmap glyphs (qsI, qsRoe, qsEt, qsSee, qsVie) keep bare-carrier joins under the old ss10 overlay but are not `SS10_UNCOVERED_BY_OLD_FONT` members, so their ss10 seam-loss rows sit UNMATCHED (the length-2 exemplars in `rebuild/out/m1/divergence-audit.tsv` name the uncovered pairs); they cost no review — every `deferred-ss10` unit machine-approves through the Junior-equivalence oracle — which is presumably why nobody noticed. Two adjacent drifts spotted at the same time: the `_ss10_isolation_completed` docstring's "an existing|existing seam never joins under the old ss10" claim is false for those pairs (the predicate stays sound through the weaker member-adjacency condition), and `classify_divergence`'s ss10 ligature arm names only three formable pairs, so ·Vie/·See/·J'ai+·Utter ss10 ligation rows fall UNMATCHED too. Repairing any of these is a deliberate conform-side decision, not a letter batch's.
- **Depth-5-only re-scorings never reach the review queue** — the exact prospect can move windows longer than the oracle's four-letter universe (the `·Day·Tea·Utter·May`-plus-fifth-letter family gained a join this way), and no oracle row exists to queue them, so the settlement-table diff is the only review surface that shows them. When an engine-scoring change lands, eyeball the `rebuild/out/m1/settlement-*.tsv` diff for such families rather than trusting the docket to surface everything — and the font side of a long-window re-scoring is checkable now instead of invisible: `make conform-deep` sweeps past the old horizon-5 wall on demand.

### Do when a gate takes too long

Not gated on a named event — these come due when a cycle step gets slow enough that acting pays off. "Slow enough" is measured, not remembered: every cycle appends host-tagged per-step wall times to `rebuild/out/cycle-timings.ndjson`, and `make cycle-timings` (`ARGS='--by-step'` for per-machine medians) is where to look before pulling any lever here. The lever inventory lives in [the speed-up tracking issue](https://github.com/adiabatic/abbots-morton-spaceport/issues/7), whose sub-issues cover each cycle step.

- **Table-build cost** — the fixpoint is the kernel crate's since the cutover ([issue #48](https://github.com/adiabatic/abbots-morton-spaceport/issues/48); `bench-the-rebuild/RUST-PORT-PLAN.md` records the port and its close): one single-threaded `build-tables` process per acceptance configuration, `--kernel-threads` of them in flight, each of which enumerates its fixpoint and folds it in place, leaving this side to pack the window payload and read a head and a treaty TSV back; `make cycle-timings ARGS='--by-step'` is the cost record to consult before pulling any lever. The crate's per-configuration peak is what caps the width — `--cache-census` prints what each memo holds — and the levers not yet taken on it are recorded in the kernel-ram survey's ranking: `u32` label ids with an end-of-run rank sort, seated cells (`Settled` as a seat, seam, extension), packed rows, and a niche for `Sym` so `Option<Sym>` is four bytes, each worth a fraction of a gigabyte per configuration. Price them in the divisor rather than in a width: `kernel_exec.CONFIG_PEAK_BYTES` is what every box divides itself by now, so halving the per-configuration peak roughly doubles the fan-out wherever the build runs. The two targets already ranked were computed for the 32 GB box — a peak near 8 GB buys it a third configuration in flight and near 4 GB a sixth, enough to cover every entry in `conform.ACCEPTANCE_CONFIGS` and turn that box's whole enumeration into one wave — and a roomier box collects the same lever sooner. The fold was the other lever and it has been taken: the crate writes the settlement and treaty TSVs, the window enumeration and the digests itself, `table.py`'s fold half and the 450 MB streams are gone, and every artifact came out byte-identical across the change. The deep-slot liveness probing and the class-grain fiber derivation (issue 26) ride inside the crate — one row per outcome fiber at the deep slots, expanded back for every fold-side consumer, so the enumeration scales with the fibers the kernel can distinguish rather than the alphabet. Since issue #78 the crate is the only fixpoint: the Python twin, the harnesses that byte-compared it against the crate and `run_m1 --engine python` are gone, and `run_font_conformance` fails fast on a stale enumeration instead of rebuilding one in process. Settlement went the same way, so `make kernel-gate` is the crate’s own gate plus the spec-ingest parity and nothing else — there is no second settler to differ against, and settlement’s regression budget is spent inside the crate. `bench-the-rebuild/scaling/scaling.py` still re-runs after each migration batch as the early warning, because the port moved the constant and not the exponent: if the ladder keeps steepening, work avoidance comes due regardless of language. Since issue #77 the sweep runs every rung through the crate — one kernel child per rung, the `build-tables` child a build runs, so a rung's peak RSS is that process's own — and prints the whole-ladder fit in both denominators; the binding constraint is still memory rather than wall clock (the top rung's kernel child sits within reach of the `RUST-PORT-PLAN.md` half-the-box row, where the Python arm used to sit at it), so read peak RSS off each run alongside the exponents, and hand a tripped run to the speed-up tracker rather than a letter batch.
- **Surface-build cost after the unit cache** — the review surface rebuilds incrementally (issue 20): the build stamps every unit with a content key over its input closure, persists a slim store beside the manifest, and on the next build serves every key-stable unit from the previous surface's shards, re-patching the order- and ledger-derived fields so a served fragment is byte-identical to what a from-scratch build would write — `rebuild/review/unit_cache.py`'s docstring is the contract, the served-vs-recomputed sample inside every build plus `rebuild/test_unit_cache.py` over the mini bundle are the proof. The store stamps no longer carry the after font's GSUB wiring (which a rune edit always moves, and which is why the cache had never once served before), so a rune-only edit now serves the units its letters cannot reach; any pipeline or review code edit still discards the store wholesale, and a cold build is about four minutes against two for a served one. The remaining levers, measured and recorded in the surface-build survey: streaming phase 2 into shards instead of materializing every fragment in the parent (the parent's pile, which `SURFACE_PARENT_BYTES` now prices and the surface-parent row of `make job-costs` keeps current, and which `surface_job_budget` subtracts from the box before dividing it by a worker — so pricing this lever in that constant rather than in a width widens the fan-out on every box at once, and on the 32 GB box it is what lifts the width off its floor of one), slimming the machine-approved fragments (issue 21 — explain and drafts are half of every shard and largest on the shard nobody opens), the prior-fragment fetch on a served build (≈26 s of parsing the previous shards), and the served-build verification sample (≈40 s; measured, it parallelizes and must stay in the worker pool). A rune edit therefore re-enriches only the windows that could feel it, and the fraction reused grows as the alphabet does; `make review-cycle ARGS='--fresh'` (or `--fresh-unit-cache` on the build CLI) bypasses the store. The load phase no longer sits outside the cache (issue 18): the ink-duplicate merge's signatures come from the persisted ink-signature store beside the unit store, keyed at the same audit-row-plus-family grain, so a steady-state pass shapes nothing there and a rune edit re-shapes only the windows that could feel it — and within the parallel phase the comparator, enricher, oracle, and drafter share one memoized shaper per font, so each (text, config) is shaped once per worker instead of up to four times. The load phase's residual floor is parsing and keying, not shaping.
- **Conform-gate cost** — `gate:conform` is the per-edit belt since the issue-74 re-charter: the exhaustive font-vs-settle sweep at horizon 4 (`--conform-horizon` on the cycle driver, passed through to `run_m1 --conform-only`; `--skip-conform` opts out; on unchanged inputs a green record auto-skips it, like every heavy cycle stage — `--fresh` forces a full rerun), about a minute at one worker per acceptance configuration, carrying the ZWNJ-structure and split-buffer checks on every boundary-bearing text since the standalone boundary gate retired, with no witness top-ups and no coverage accounting: read-back proves per build that the font holds every planned rule, `rebuild/test_rule_witnesses.py` stays the font-free dead-rule alarm, and the sweep’s charter is HarfBuzz application semantics plus the sufficiency of the window abstraction itself. It no longer sits in the look-edit-look loop’s critical path: a `make review-cycle` pass that rebuilds anything defers it to the next pass, so the sweep’s cost lands on the converging pass rather than between an edit and seeing the letters. Settlement is memoized per distinct raw window (`conform._SettledWindowWalk`): the walk batches its misses through the crate’s `settle-cases` and every recurrence across the sweep’s texts is a dict probe, so a stream’s marginal cost is the uharfbuzz shape — the memo keys on the raw window up to the fourth slot and consults no liveness oracle (since issue #78: measured faster than the probe-normalized keying it replaced). What that keying still buys is independence from the crate’s enumeration and fold, not a second engine: the settlement underneath is the one the tables were built from, and what the sweep proves is HarfBuzz’s application of them plus the sufficiency of the window abstraction. It is alarmed by `rebuild/test_conform.py`’s walk-equivalence sweeps, and the sweep inherits the ZWNJ/split-buffer checks within the horizon the boundary gate already proved for the same font bytes (the boundary summary carries `max_length`/`configs`/`font_sha256` exactly so `conform.proven_boundary_horizon` can decline when any of that moved). Depth lives in the periodic deep sweep now: `make conform-deep` runs the same sweep at horizon 5+ overnight or on demand, its green keyed on the emitted lookup’s behavior classes (`emit_gsub.behavior_classes`, fail-closed) plus the font-compilation code and the uharfbuzz version rather than on the runes, so it stays green across rune edits that introduce no novel rule shape, and every cycle prints whether it is current or armed. When the belt becomes the cycle’s long pole again, the lever is still `--conform-horizon`, decided deliberately — a cost knob now, not a coverage knob.

- **The review tab's heap** — the tab's resident set is the review queue now rather than the corpus: the app boots by streaming `app-units.ndjson.gz`, one slim row per unit awaiting a verdict, and Range-fetches `explain`/`drafts` back out of the class shard when a panel opens (`rebuild/review/README.md`'s "What the tab holds" and REVIEW-PLAN §7.4 are the description; `rebuild/review/app_index.py` is the writer). So the heap grows with the human workload rather than with each migrated letter, and the four-gigabyte Chromium cap the docket used to hit is no longer the near ceiling it was — `performance.memory.usedJSHeapSize` after the docket loads is still the measurement, and it is what says when any of the levers below comes due. Three remain, in the order they would bite. The show-machine folds are the one path that still parses whole class shards, single-slot and evicted on leaving, so opening a fold on a large machine class is a transient cliff; the lever there is rendering a fold's rows in windows off the locator's byte spans instead of off the class's shards. The slim rows themselves still scale with the queue, and the next thing to drop from them is `text_entities`/`highlight`/`after.cells`, Range-fetched per rendered card the way explain already is. And the locator is re-streamed per machine deep link by design (a worklist resolves once and pins what it found, so only a fresh deep link pays); if a sitting ever chases many machine ids, write the locator in unit-number order and binary-search it with Range requests, which is a format change rather than a code change. Issue 21's build-side slimming of the machine-approved fragments is a separate, still-open lever — see "Surface-build cost after the unit cache" above; the two are independent, and the byte spans keep working wherever a fragment is written.
- **Validators-lane cost** — the lane holds only assertions about the live artifact that no build check makes — `rebuild/conftest.py` is the authority on which tests those are — and runs in about two minutes at `VALIDATORS_WORKERS`, its long pole the rule-witness arms, one per `conform.ACCEPTANCE_CONFIGS` entry, at roughly forty seconds each; the lever recorded for them is the kernel emitting each rule's shortest realizing prefix into the windows head so the build fails on a dead rule and the lane only re-settles the recorded witness (validators survey part C, P2). `built_review_surface` refuses a stale surface rather than building one, so a bare `make test-rebuild` after an edit wants a surface build first.
- **Baseline-oracle cost after the settlement cutover** — `run_m1`'s `run_oracle` phase (the §13.1 old-font oracle) settles its rows through the crate's `settle-cases` now that the Python engine is gone, in chunked waves off a `conform._SettledWindowWalk` of its own. The phase was watched closely across the cutover as the one place a per-row settle could have become a per-row kernel spawn; measured uncontended it now finishes faster than the in-process engine did, so nothing is owed here. Two cautions for whoever reads its number next: it is sensitive to what else the cycle is running (a pass whose `gate:make-test` overlaps it reads far slower than one whose does not, which is enough to invent a regression that is not there — compare like against like in `make cycle-timings ARGS='--by-step'`), and the levers left if it ever does become the pole are sharing the belt's memo rather than building a second walk per configuration (the oracle's rows are the same texts the belt sweeps) and a larger `kernel_exec.SETTLE_WINDOW_BATCH`.
- **A classifier or ledger edit still costs a table rebuild** — `pipeline_code` folds every `rebuild/pipeline/*.py` and the crate into the stamp the serialized enumeration carries, so an edit to the oracle's classifier re-runs `run_m1` and the belt to produce byte-identical tables (issue #81). `run_m1 --gates-only` re-runs the Manual-pin gate and the oracle over the build on disk for a by-hand check, but records no green; the remaining piece is splitting the code closure into a table side (the crate, spec loading, the emitters) and a comparison side (conform's oracle and ledger matching, the validation shaper), mechanically checked by an import-graph test, so a comparison-side edit can skip the build honestly. The same move would let the cycle keep the review server up through a gate pass (the plumbing survey's P2): today any pass that writes the store stops it, and a sitting always writes the store.

## Keeping this file honest

This is a punch list of what’s _left_ — not a changelog of what happened. When a landed change leaves a genuinely-open residue, record the residue as a forward bullet, not the change that produced it.
