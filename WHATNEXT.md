# What next

The living punch list for the Abbots Morton Spaceport rebuild — the forward-looking companion to the per-milestone plans under `rebuild/`. It records what ought to happen next, the open forks in the road, and the deferred work we have consciously parked. Keep it current: see “Keeping this file honest” at the bottom.

## The main thread — M1 rune migration

The rebuild is migrating the cursive-join engine rune by rune, validating each batch against the old shipped font via the oracle.

**Current frontier: the qsThaw batch is built and awaits its sitting, and the qsGay sitting is still open.** `rebuild/M1-BATCH20-PROGRESS.md` (qsGay) and `rebuild/M1-BATCH21-PROGRESS.md` (qsThaw) are the two bounded scratch files; each records its open sitting questions, design overrides, and verification recipe, and each should be deleted when its sitting closes its batch. ·Thaw is the alphabet's first entry-only rune — fifteen lefts join its baseline entry, it joins nothing rightward until qsIng migrates, and the old after-tall stance dissolved into allowlist scoping — and it needed no new ledger class, joining `SS10_UNCOVERED_BY_OLD_FONT` on the qsOut entry-side-only precedent. `make verdict-ready` is the standing check, `glyph_data/runes/` is the roster of what has already migrated, and `make novelty-order` is the way into the blanks that remain.

**Migrating a letter needs no hand-update anywhere in the rebuild suite.** No artifact count is hardcoded — `test_review_enrich`'s subset-table row count is a containment over the frozen mini bundle — and the frozen bundle itself is content-addressed, so a regeneration after a migration moves bytes rather than numbers a reader has to re-derive. What a regeneration can refuse is a worked-example window that stopped selecting any audit row, and it names the window, which is a prompt rather than a hand-update. The census needs no re-baseline: every artifact-cycle pass rewrites `rebuild/review-census-pins.json` from the census sidecar the build already emitted and prints its git diff, so the alphabet-coupled counts it carries are reviewed and accepted at commit time. The ledger's `no_verdict` set, the form-guard class membership, the doc-table row count, and the ledger-exemplar count are derived at test time from the loaded ledger, the settle verdicts, and `LETTERS`. The subset tables refilter themselves, because `run_m1` runs `baseline_subset.ensure_fresh` before anything else, so an `M1_ALPHABET` edit cannot feed the oracle stale subset tables. `rebuild/m1-aliases.yaml` still needs authoring, but `run_m1` refuses to start while any subset-row glyph name lacks an entry, naming the missing names (an entry may map to the literal `pending` to acknowledge a name mid-migration), so the build prompts for the aliases instead of silently miscounting.

**Where the state lives:** `make verdict-ready` — and the same status as a banner in the app — answers whether the surface, gates, and verdict store are ready: surface freshness by input fingerprint and against the M1 font under the served letters, gate greenness, verdict-store alignment, the frontier carry, blanks remaining, server. `rebuild/out/cycle_summary.json` is the last cycle’s own record (surface units and echo groups, unmatched oracle rows, each gate’s status, and the `verdicts-carried-<sha>.json` it wrote with how many verdicts rode it); the per-gate summaries under `rebuild/out/m1/` hold the rest (`conform_summary.json`, `manual_pins_summary.json`, `readback_summary.json`, `oracle_summary.json`); the store itself is `verdicts-autosave.json`, journaled in `verdicts-journal.ndjson`, which the newest verdicts ride until the next cycle’s carry; and `make complaint-docket` clusters the open reject/neither verdicts by the rune records that decided them. Read those; don’t copy their numbers back into this file, where they go stale the next time a cycle runs.

**The standing shape of the gates**, which is what a number here would have been trying to say: the crate's string replay holds every build's tables to its own engine over every string of the belt's universe (`run_m1.REPLAY_HORIZON`; `rebuild/out/m1/replay_summary.json` is its record), the conform belt is exact — zero divergences at horizon 4 over the settlement configurations, and over the ss10 overlay's two-letter arm, which read-back's isolation proof makes complete — and since the standalone boundary gate retired it carries the split-buffer check itself (`make conform-deep` carries it at 5+); read-back proves the font holds the planned rules and its boundary glyphs inert, and the build's witness stage proves every rule reachable by settling the certificate the crate wrote beside it; the Manual pins replay clean under the no-waiver gate, scope included; and the M1 GSUB rides type-7 Extension offsets by design (`m1_settle` is `useExtension`), inside the subtable-offset headroom floor read-back holds it to. The oracle’s remaining unmatched rows are verdict-gated divergences from the old font, not failures — among them the deliberate ss03 ·Fee·Tea divergence, where the rune extends by 1 per the old derive’s stated intent and the divergence lands through verdicts with no ledger entry. The docket’s standing complaints are windows already argued and accepted, so a _fresh_ complaint is the signal. The artifact cycle lands the echo prefill and the checked-in standing approvals (`rebuild/standing-approvals.yaml`) itself after its carry+merge, so only genuinely new questions ever queue — and echo groups key on the localized ink delta, which puts unchanged flanking letters, including followers that merely slid over by an advance change, outside the grain.

## Deferred and tracked follow-ups

### Doable anytime

Nothing gates these — act on any cycle, whenever it’s worth it.

- **The shipped first-match order of the settlement lookup is proven by the belt alone.** `doc/rebuild-design.md` §10's fault-coverage table measured it (row 6): two rules of one input swapped inside `emit_gsub._ordered_settle_rules` leave the fold, the string replay, the witness stage, read-back and the whole run_m1 gate green, and only gate:conform sees the text that now settles differently. The belt's key moves on code and on behavior classes, not on rune content, so an ordering fault that a rune edit exposes without minting a new shape waits for the next code change or deep sweep. The check that would close it is a first-match replay of `emit_gsub.fold_settle_rules`' emitted order against each configuration's rows inside the build, O(rows). Two smaller residues from the same table: `certificate::certify` answers the empty list for a mis-pinned row whose chain it cannot spell, so the witness stage refuses on the certificate count instead of the crate naming the rule and the pin; and a fault confined to the deep slots behind a letter left (row 4) is beyond every horizon-4 gate, where a per-family `replay-strings` walk at horizon 5 costs about a minute per configuration.

- **`·Key·Utter·May` breaks before the alternate ·Utter where every other baseline-reaching left joins.** Two records manufacture that shape — a qsUtter refuse of the mono x-height exit scoped to left ·Key right ·May, plus a qsKey yielding prefer to break the resulting tie — and they exist only to hold the Manual pin at `site/the-manual.html:3985`, which entered the no-waiver Manual-pin gate's scope when ·Key migrated. [Issue #103](https://github.com/adiabatic/abbots-morton-spaceport/issues/103) is the live proposal — the normal ·Utter by default, the Manual's shape behind a stylistic set with the pinned word wrapped to switch it on — and holds the measurements and the routes, the blast radius among them: striking both records leaves `run_m1` green and the Manual-pin gate failing on that one pin alone, with nothing else in the alphabet moving.
- **The ss10 uncovered-set has pre-existing holes batch 13 measured but did not repair.** Five migrated runes whose anchors ride their base cmap glyphs (qsI, qsRoe, qsEt, qsSee, qsVie) keep bare-carrier joins under the old ss10 overlay but are not `SS10_UNCOVERED_BY_OLD_FONT` members, so their ss10 seam-loss rows sit UNMATCHED (the length-2 exemplars in `rebuild/out/m1/divergence-audit.tsv` name the uncovered pairs); they cost no review — every `deferred-ss10` unit machine-approves through the Junior-equivalence oracle — which is presumably why nobody noticed. Two adjacent drifts spotted at the same time: the `_ss10_isolation_completed` docstring's "an existing|existing seam never joins under the old ss10" claim is false for those pairs (the predicate stays sound through the weaker member-adjacency condition), and `classify_divergence`'s ss10 ligature arm names only three formable pairs, so ·Vie/·See/·J'ai+·Utter ss10 ligation rows fall UNMATCHED too. Repairing any of these is a deliberate conform-side decision, not a letter batch's.
- **Depth-5-only re-scorings never reach the review queue** — the exact prospect can move windows longer than the oracle's four-letter universe (the `·Day·Tea·Utter·May`-plus-fifth-letter family gained a join this way), and no oracle row exists to queue them, so the settlement-table diff is the only review surface that shows them. When an engine-scoring change lands, eyeball the `rebuild/out/m1/settlement-*.tsv` diff for such families rather than trusting the docket to surface everything — and the font side of a long-window re-scoring is checkable now instead of invisible: `make conform-deep` sweeps past the old horizon-5 wall on demand.
- **A tool run by hand still prints raw.** The digest is the artifact cycle's alone: the plan block, the per-step banners, the per-step logs under `tmp/build-logs/` and the closing table are the driver's rendering of what its children print, so running one of those children on its own (`run_m1`, the review build) shows its `[t]` / `[phase]` / `[progress]` / `[warn]` lines as plain prefixed text among everything else it says, which is what `rebuild/tools/console.py`'s producer half promises and no more. That was scoped out deliberately rather than missed — a standalone digest first wants an answer to what a tool's plan and step list even are — so reach for it when a hand-run tool's output is what is actually costing someone time.

- **The ·Tea·Day tight bond is per-rune and must be re-checked at every migration** — the standing taste is that a ·Tea·Day pair keeps its forward join, so nothing upstream may spend ·Tea’s one baseline slot backward (qsTea.full’s `pairings.never` makes that slot exclusive). The one standing exception is ·Et, made by the shipped font itself: after ·Et, ·Tea takes the backward baseline join and strands ·Day, and qsTea’s own records already carry it (the two `left: qsEt` row-grain refusals plus the ss05 both-baseline unlock scoped to the same left), so the qsEt migration needed neither shape below. No ·Tea→·Day seam in the migrated alphabet may lose its forward join; holding that as letters arrive takes records in two shapes, and a new rune may need either. **The ordinary shape** is the yielding prefer already idiomatic on qsDay and qsNo — `{cell: {exit: none}, over: {exit: baseline}, when: {right: {family: qsTea, then: {family: qsDay}}}}`, default `yields-to-joins`, no `why` demanded — which any newly-migrated family that can exit into ·Tea will want. qsJai carries the broadest variant on record: the old font yields ·J'ai's ·Tea join to every follower ·Tea can actually serve, so its record scopes `then: {except: [{family: qsPea}]}` rather than naming followers — ·Pea is excepted because half-·Tea could serve it at the x-height and the tie would otherwise flip. qsAwe, qsOx, qsEight, qsOoze, and qsBay carry the same record verbatim, on the same oracle shape. **The ·Utter shape** lives on qsUtter alone now that follower votes read their real shifted slots: a `mode: absolute` stance vote — `{stance: mono, when: {right: {family: qsTea, then: {family: qsDay}}}}` — withholds any predecessor’s x-height reach into ·Utter when ·Tea·Day follows (·Utter’s `alternate` stance is the one place whose exit is mandatory, `require: [exit]`, so that reach forces the stranding from two positions away), and the own-chain record `{right: {family: qsUtter, then: {family: qsTea, then: {family: qsDay}}}}` survives beside it for the one seat a vote structurally cannot reach — ·Utter after ·Utter, where a record whose owner is the seat’s own rune is read through the own-rune branch. A newly-migrated family entering qsUtter’s x-height `from:` list needs no copy of anything — the vote covers it from qsUtter’s side automatically; what a migration still owes is the oracle spot-check that the new family’s `X·Utter·Tea·Day` windows land old-font. `absolute` is load-bearing on both records, because the joining candidate outscores the yielding one on join-count and a default-mode record is a total no-op.

## Keeping this file honest

This is a punch list of what’s _left_ — not a changelog of what happened. When work lands, edit the current-state description in place and delete the status it supersedes; never append a dated `Update (…)` paragraph. What got done — with what counts, and under which commits — is already in the git log, so this file records only the live frontier: the open forks, the next batch, and the consciously-parked follow-ups. When a landed change leaves a genuinely-open residue, record the residue as a forward bullet, not the change that produced it. The broader workflow rules — no after-the-fact reports, bounded progress files, evidence that outlives its decision — live in `AGENTS.md`’s “Note-taking and the rebuild logs” section; `AGENTS.md` points back here.
