Turn a "stop asking me about this" complaint into a rule in `rebuild/standing-approvals.yaml`, applied every cycle by `rebuild/tools/standing_verdicts.py`. The named unit is a specimen of a phenomenon; the job is every window that shows that change, not the specimen's digest family. The tool's module docstring is the authority on what each rule shape proves — every shape in its `SHAPES` table, and the composed reading that lets two rules explain one window between them — so read it first and do not restate its contracts here or anywhere else.

## Hard rules

- The decision is the user's; the rule only records it. Find where it was made (a verdict family, a rune edit, a sitting note) before writing anything, and cite it in the rule's `note:`. Never author a rune `why:` — that voice is the user's — but the `note:` in `standing-approvals.yaml` is agent-written, in the file's own idiom.
- A rule must fill the whole surveyed phenomenon and nothing else. Every shape has a blind spot, stated in its docstring; before landing a rule, list the blank units it would fill and read each one against that blind spot.
- Never hand-write the verdict store or any `verdicts-*.json`; the cycle lands the fill through `merge_verdicts`. Never join unit ids across manifests.
- Counts belong to the dry run's output and the cycle summary, never to prose or the rule's note.
- If none of the checked-in shapes as they currently match can name the whole survey, extend the matcher in `rebuild/tools/standing_verdicts.py` (and the probe when it enumerates the cells) until one can — that is this skill's job. Teaching extension-dropped a kept `ex-ext-M`, a follower list, or `ex-con-N`, adding slide when two ink-delta digests left the rest of ·See queuing, and adding redrawn when ·Eight's pulled-in bowl fit no pixel contract, were that work. A whole new shape is the last move, still this skill's (tests in the file's idiom, a matcher docstring).

## Steps

1. **Probe the units.** `uv run python rebuild/tools/standing_probe.py u-NNNNNN …` (read-only; reads the live autosave for blankness). Users often name the change rather than a unit, in the corpus `data-expect` minilanguage (`·Tea.half ~x~ ·No` → `·Tea ~b~ ·No`): `doc/data-expect.md` is the grammar, and `parse_expect` in `test/test_shaping.py` is the authority. `--find TEXT` is the route from that prose to a specimen — a plain substring match over every human unit's notation, blanks first and capped with the total stated, narrowed by `--blank-only` and `--limit N` — and with the surface already open in front of the user, `/` in the review app searches the same units while each row's Copy button puts a prompt preamble for that unit on the clipboard, which is the same route with the user's own eyes on it. For each unit the probe prints the two grains side by side — recorded glyphs/cells/seams, and the rendered pieces of both fonts with placement, own-frame origin and cell count, read as "same shape placed N columns over", "redrawn", or "inkless" — then what every checked-in rule makes of it, what the composed reading credits, and how many human units share exactly its ink-delta digests and how they were verdicted. Name every change in the window from that table before going further: a slide (same shape, origin and placement moved), a dropped extension (redrawn by exactly the tail, follower placed closer), a re-spelling (pieces differ, picture does not), or something else.
2. **Survey the swath.** The named unit is a specimen. After naming the change, enumerate every human unit that shows it: `--extension-cells` for an exit stretch; for a slide or a redraw, every window whose rendered pieces carry the same pivot move or the same own-frame cell appearing or disappearing. That set is the job. The specimen's digest family is evidence the user already approved the change; it is not the fill target.
3. **Find the decision's record.** The survey's already-verdicted members usually show the user has already approved the change through echo; `git log -S<token> -- glyph_data/runes/qs<Family>.yaml` finds the rune edit that made it (a narrowed `extend:` list, a dropped record) and its commit subject; a sitting's parked question lives in `WHATNEXT.md` or the batch progress file. If none of these exists, the change is not yet decided — stop and ask, because a rule would be inventing a verdict.
4. **Pick the smallest home, in this order.** A rule's shape is which key its `match.after` carries, never its id; `SHAPES` in `rebuild/tools/standing_verdicts.py` is the map from key to shape. (a) An existing rule that already names the phenomenon and merely lacks a pivot form, follower, cell or digest — extend it, and `uv run python rebuild/tools/standing_probe.py --coverage RULE_ID` re-runs that rule's own survey relaxed of everything it names, so the candidates arrive as a docket with a verdict tally each rather than as a guess. (b) Two existing rules that each explain part of the window — no rule at all: the composed reading fills it once both rules exist, and the probe's `composed:` line says whether it does and which rules it credits. (c) A new rule in the structural shape that names the change: `uv run python rebuild/tools/standing_probe.py --shapes` prints the menu, walked off the `SHAPES` table itself, each row with the symptom its own matcher opens with. Read the probe's rendered-grain reading of the window against that menu, pick the row whose symptom is the change you named in step 1, then read that matcher's own docstring for what it proves and — the part that decides whether the rule is honest — where it is blind. (d) An `ink-delta` rule only when the survey is a single digest — the change never rides beside anything else. Two or more digests for the same change means a companion is minting new identities; a structural shape is required, and if no shape in the menu names the survey as it currently matches, extend the matcher (back to (c)) rather than listing those digests.
   - A shape that names cells has to have them enumerated before a rule in it can be written, and the probe does that enumeration: `--extension-cells PIVOT TOKEN SEAM` for an extension-dropped rule, where `TOKEN` is the `ex-ext-N` the before glyph carried or the `ex-con-N` the after cell carries, and `--retarget-cells PIVOT BEFORE_SEAM FOLLOWER AFTER_SEAM` for a join-retargeted or join-created one. Each prints every pivot cell, follower family and follower cell the rule must name, with a verdict tally per pair, in code-point order — name them all, and set `follower:` to the family list. `--coverage` is the same enumeration turned on a rule that already exists, which is why rung (a) reaches for it.
5. **Write the rule and dry-run it.** Append to `rebuild/standing-approvals.yaml`; then `uv run python rebuild/tools/standing_verdicts.py verdicts-autosave.json --out tmp/standing-dry.json`. The run prints a line per rule and per composed credit, then a per-rule rollup that adds each rule's composed credit to what its own line accounts for: read the rollup, not the own line alone. That is the distinction that misleads — the composed pass claims a window before any single rule is asked about it, so a composable rule's own line counts only the windows no composition took, and a rule reading small there may already be reaching the whole survey through credit. Check the rollup before concluding the matcher needs widening; the run says in its own words when a rule reached nothing at all, and it also flags what a block of numbers hides — a matched unit carrying a verdict outside the approve/either set, which is the shape an over-broad rule takes from outside, and an `except_left` family no window on this surface joins from. `--explain RULE` prints that rule's matched unit ids split the same way its line counts them, which is what the coverage check needs: filled plus already-verdicted plus held must cover the survey, held only by `except_left`. Probe each filled unit that is not in the survey and confirm nothing else changed in it — an `extension-dropped` rule cannot see a slide or a re-spelling elsewhere in the window, so a fill of that shape is only as honest as the surface's `pair` and `secondary_seams` fields. A rollup short of the survey sends you back to step 4, usually to extend the matcher, not to append another digest.
6. **Test and gate.** Add positive and negative contract cases in the file's idiom only when the matcher moved — the new contract's positive, its negative, and, if the shape is composable, its composed-walk case. A rule landing under an unchanged matcher needs no test of its own: `load_rules` validates every checked-in rule's shape and the contracts lane runs it over the real file on every pass, the validators lane holds that every checked-in rule still reaches the live surface, and the dry run's tally is what actually says how far the rule reaches. `uv run pytest rebuild/test_standing_verdicts.py -n auto --dist worksteal` is the loop while writing those cases, not a gate step. The gate itself is `make prettier` and then `make test-rebuild`, both in the foreground with an explicit long Bash timeout rather than detached, because the next step must not start until they answer. Pyright needs no line of its own: the PostToolUse hook in `.claude/settings.json` runs it on every Python write, and `make test-rebuild` runs it again inside the suite. Ordering is a constraint and not a preference here — both lanes' green records key on the file list `rebuild_gate_closure_files` in `rebuild/tools/artifact_cycle.py` returns, which holds `rebuild/standing-approvals.yaml` and the test file among the rest of `rebuild/`, so anything in that closure changing between this gate and the cycle in step 7 makes the cycle re-run both lanes inside itself. Land every edit first, gate last.
7. **Land it.** Commit in reader terms ("Stop having to verdict …"). Then run the cycle in the foreground with an explicit long Bash timeout: `make review-cycle SERVE=0`, or `make review-cycle SERVE=bg` for the same pass with the review app back up in the same command — it waits for the port before returning, so a `make verdict-ready` on the next line reads a server that is up rather than one still starting. The server comes down for this pass and cannot be arranged otherwise: the cycle's verdict-plumbing key folds in `rebuild/standing-approvals.yaml`'s bytes, so a rule landing always moves it, the plumbing always runs, the store is always written, and `server_may_stay_up` in `rebuild/tools/artifact_cycle.py` grants its reprieve only to a pass that writes neither the surface nor the store. Set that timeout from `make cycle-timings ARGS='--by-step'`, which reports this machine's own step medians — no duration written down here would survive the next box. Finish with `make verdict-ready`, and report the rule's line from the cycle summary and the census diff the cycle printed.

## What this costs when skipped

Each of these was rediscovered by hand once and is why the probe exists: the same change in a different window carries a different whole-window digest as soon as any other change rides beside it, so an ink-delta family's approvals prove the decision but cannot fill the composed window — listing the specimen's digest (and one composed companion) leaves the rest of the swath on the docket, which was the first ·See rule; "for real this time" taught slide so every window with that column drop filled, including ones that also carry a blessed extension; the structural extension shape fills blindly past anything that is not a seam, so its dry-run fills must be read, not counted; the rendered fonts position through GPOS, so never reason about a slide from `hmtx` advances — the probe reads shaped placements; a `slide` rule refuses on one stray pixel by design, and a window pairing a blessed slide with a blessed extension drop is the composed reading's case, not a new rule's; and an already-verdicted echo family is evidence for a rule, not a substitute for one — echo only reaches pixel-identical lookalikes, a rule reaches windows the user has never seen.

## Scratch discipline

`tmp/standing-dry.json` and any survey output are scratch and never committed. The durable outcome is the rule, its tests, and the commit message; the fill itself lands through the cycle.
