Turn a "stop asking me about this" complaint into a rule in `rebuild/standing-approvals.yaml`, applied every cycle by `rebuild/tools/standing_verdicts.py`. The named unit is a specimen of a phenomenon; the job is every window that shows that change, not the specimen's digest family. The tool's module docstring is the authority on what each rule shape proves — the `ligature`, `extension-dropped`, `ink-delta` and `slide` shapes, and the composed reading that lets two rules explain one window between them — so read it first and do not restate its contracts here or anywhere else.

## Hard rules

- The decision is the user's; the rule only records it. Find where it was made (a verdict family, a rune edit, a sitting note) before writing anything, and cite it in the rule's `note:`. Never author a rune `why:` — that voice is the user's — but the `note:` in `standing-approvals.yaml` is agent-written, in the file's own idiom.
- A rule must fill the whole surveyed phenomenon and nothing else. Every shape has a blind spot, stated in its docstring; before landing a rule, list the blank units it would fill and read each one against that blind spot.
- Never hand-write the verdict store or any `verdicts-*.json`; the cycle lands the fill through `merge_verdicts`. Never join unit ids across manifests.
- Counts belong to the dry run's output and the cycle summary, never to prose or the rule's note.
- If none of the four shapes as they currently match can name the whole survey, extend the matcher in `rebuild/tools/standing_verdicts.py` (and the probe when it enumerates the cells) until one can — that is this skill's job. Teaching extension-dropped a kept `ex-ext-M`, a follower list, or `ex-con-N`, and adding slide when two ink-delta digests left the rest of ·See queuing, were that work. A fifth shape is the last move, still this skill's (tests in the file's idiom, a matcher docstring).

## Steps

1. **Probe the units.** `uv run python rebuild/tools/standing_probe.py u-NNNNNN …` (read-only; reads the live autosave for blankness). Users often name the change in the corpus `data-expect` minilanguage (`·Tea.half ~x~ ·No` → `·Tea ~b~ ·No`): `doc/data-expect.md` is the grammar, and `parse_expect` in `test/test_shaping.py` is the authority. For each unit it prints the two grains side by side — recorded glyphs/cells/seams, and the rendered pieces of both fonts with placement, own-frame origin and cell count, read as "same shape placed N columns over", "redrawn", or "inkless" — then what every checked-in rule makes of it, what the composed reading credits, and how many human units share exactly its ink-delta digests and how they were verdicted. Name every change in the window from that table before going further: a slide (same shape, origin and placement moved), a dropped extension (redrawn by exactly the tail, follower placed closer), a re-spelling (pieces differ, picture does not), or something else.
2. **Survey the swath.** The named unit is a specimen. After naming the change, enumerate every human unit that shows it: `--extension-cells` for an exit stretch; for a slide or a redraw, every window whose rendered pieces carry the same pivot move or the same own-frame cell appearing or disappearing. That set is the job. The specimen's digest family is evidence the user already approved the change; it is not the fill target.
3. **Find the decision's record.** The survey's already-verdicted members usually show the user has already approved the change through echo; `git log -S<token> -- glyph_data/runes/qs<Family>.yaml` finds the rune edit that made it (a narrowed `extend:` list, a dropped record) and its commit subject; a sitting's parked question lives in `WHATNEXT.md` or the batch progress file. If none of these exists, the change is not yet decided — stop and ask, because a rule would be inventing a verdict.
4. **Pick the smallest home, in this order.** (a) An existing rule that already names the phenomenon and merely lacks a pivot form, follower, cell or digest — extend it. (b) Two existing rules that each explain half the window — no rule at all: the composed reading fills it once both rules exist, and the probe's `composed:` line says whether it does. (c) A structural `extension-dropped` rule for a dropped or shortened exit extension, or for an exit contraction — a shortening names the kept `ex-ext-M` in its pivot cells, a contraction names `ex-con-N` as `exit_extension` and on every pivot cell (the before glyph carrying no exit extension), and the shape speaks for the columns between — `uv run python rebuild/tools/standing_probe.py --extension-cells qsX ex-ext-N y0` (or `ex-con-N`) enumerates every pivot cell, follower family and follower cell it must name, with each pair's verdict tally; name them all, in code-point order, and set `follower:` to the family list. (d) A `slide` rule for a letter re-spaced against its predecessor. (e) An `ink-delta` rule only when the survey is a single digest — the change never rides beside anything else. Two or more digests for the same change means a companion is minting new identities; a structural shape is required, and if the current matcher cannot name the survey, extend it (back to (c) or (d)) rather than listing those digests.
5. **Write the rule and dry-run it.** Append to `rebuild/standing-approvals.yaml`; then `uv run python rebuild/tools/standing_verdicts.py verdicts-autosave.json --out tmp/standing-dry.json` and read the rule's line (`N filled, M already verdicted, K held`). Filled + already-verdicted + held must cover the survey (held only by `except_left`). A small subset means the rule is incomplete — go back to step 4, usually to extend the matcher, not to append another digest. Probe each filled unit that is not in the survey and confirm nothing else changed in it — an `extension-dropped` rule cannot see a slide or a re-spelling elsewhere in the window, so a fill of that shape is only as honest as the surface's `pair` and `secondary_seams` fields.
6. **Test and gate.** Add the rule to `test_checked_in_rules_file_loads` in `rebuild/test_standing_verdicts.py` plus one positive and one negative structural case in the file's idiom. If the matcher moved, add the new contract's positive, negative, and (if composable) composed-walk cases in the file's idiom, not only the checked-in rule. Then `uv run pytest rebuild/test_standing_verdicts.py -n auto --dist worksteal`, `make prettier`, `uv run pyright`, then `make test-rebuild` detached (`rebuild/` is outside `make test`'s closure, so do not force that gate).
7. **Land it.** Commit in reader terms ("Stop having to verdict …"), then run the cycle detached — `nohup caffeinate -i make review-cycle SERVE=0 > tmp/cycle-pass.log 2>&1 &` — which stops the review server itself because the standing fill writes the store, and when its banner lands restart the server (`nohup uv run python -m rebuild.review.serve > tmp/review-serve.log 2>&1 &`) and confirm with `make verdict-ready`. Report the rule's line from the cycle summary and the census diff the cycle printed.

## What this costs when skipped

Each of these was rediscovered by hand once and is why the probe exists: the same change in a different window carries a different whole-window digest as soon as any other change rides beside it, so an ink-delta family's approvals prove the decision but cannot fill the composed window — listing the specimen's digest (and one composed companion) leaves the rest of the swath on the docket, which was the first ·See rule; "for real this time" taught slide so every window with that column drop filled, including ones that also carry a blessed extension; the structural extension shape fills blindly past anything that is not a seam, so its dry-run fills must be read, not counted; the rendered fonts position through GPOS, so never reason about a slide from `hmtx` advances — the probe reads shaped placements; a `slide` rule refuses on one stray pixel by design, and a window pairing a blessed slide with a blessed extension drop is the composed reading's case, not a new rule's; and an already-verdicted echo family is evidence for a rule, not a substitute for one — echo only reaches pixel-identical lookalikes, a rule reaches windows the user has never seen.

## Scratch discipline

`tmp/standing-dry.json` and any survey output are scratch and never committed. The durable outcome is the rule, its tests, and the commit message; the fill itself lands through the cycle.
