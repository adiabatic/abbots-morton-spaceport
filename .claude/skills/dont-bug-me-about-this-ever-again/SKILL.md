Turn a "stop asking me about this" complaint into a rule in `rebuild/standing-approvals.yaml`, applied every cycle by `rebuild/tools/standing_verdicts.py`. The tool's module docstring is the authority on what each rule shape proves — the `ligature`, `extension-dropped`, `ink-delta` and `slide` shapes, and the composed reading that lets two rules explain one window between them — so read it first and do not restate its contracts here or anywhere else.

## Hard rules

- The decision is the user's; the rule only records it. Find where it was made (a verdict family, a rune edit, a sitting note) before writing anything, and cite it in the rule's `note:`. Never author a rune `why:` — that voice is the user's — but the `note:` in `standing-approvals.yaml` is agent-written, in the file's own idiom.
- A rule must fill exactly the decision and nothing else. Every shape has a blind spot, stated in its docstring; before landing a rule, list the blank units it would fill and read each one against that blind spot.
- Never hand-write the verdict store or any `verdicts-*.json`; the cycle lands the fill through `merge_verdicts`. Never join unit ids across manifests.
- Counts belong to the dry run's output and the cycle summary, never to prose or the rule's note.
- Do not invent a new shape before the existing four, the composed reading, and an extension of an existing rule have all been ruled out — and if one is needed, it is a design task with tests and a review, not a rule edit.

## Steps

1. **Probe the units.** `uv run python rebuild/tools/standing_probe.py u-NNNNNN …` (read-only; reads the live autosave for blankness). For each unit it prints the two grains side by side — recorded glyphs/cells/seams, and the rendered pieces of both fonts with placement, own-frame origin and cell count, read as "same shape placed N columns over", "redrawn", or "inkless" — then what every checked-in rule makes of it, what the composed reading credits, and how many human units share exactly its ink-delta digests and how they were verdicted. Name every change in the window from that table before going further: a slide (same shape, origin and placement moved), a dropped extension (redrawn by exactly the tail, follower placed closer), a re-spelling (pieces differ, picture does not), or something else.
2. **Find the decision's record.** The digest family's verdict tally usually shows the user has already approved the change hundreds of times through echo; `git log -S<token> -- glyph_data/runes/qs<Family>.yaml` finds the rune edit that made it (a narrowed `extend:` list, a dropped record) and its commit subject; a sitting's parked question lives in `WHATNEXT.md` or the batch progress file. If none of these exists, the change is not yet decided — stop and ask, because a rule would be inventing a verdict.
3. **Pick the smallest home, in this order.** (a) An existing rule that already names the phenomenon and merely lacks a pivot form, follower, cell or digest — extend it. (b) Two existing rules that each explain half the window — no rule at all: the composed reading fills it once both rules exist, and the probe's `composed:` line says whether it does. (c) A structural `extension-dropped` rule for a dropped or shortened exit extension, or for an exit contraction — a shortening names the kept `ex-ext-M` in its pivot cells, a contraction names `ex-con-N` as `exit_extension` and on every pivot cell (the before glyph carrying no exit extension), and the shape speaks for the columns between — `uv run python rebuild/tools/standing_probe.py --extension-cells qsX ex-ext-N y0` (or `ex-con-N`) enumerates every pivot cell, follower family and follower cell it must name, with each pair's verdict tally; name them all, in code-point order, and set `follower:` to the family list. (d) A `slide` rule for a letter re-spaced against its predecessor. (e) An `ink-delta` rule only for a change no structural shape can name, remembering that any other change riding in the same window mints a different digest and orphans it.
4. **Write the rule and dry-run it.** Append to `rebuild/standing-approvals.yaml`; then `uv run python rebuild/tools/standing_verdicts.py verdicts-autosave.json --out tmp/standing-dry.json` and read the rule's line (`N filled, M already verdicted, K held`). The already-verdicted count should agree with the digest family's tally; the filled units should be exactly the complaint's windows and their lookalikes. Probe each filled unit that is not one of the named windows and confirm nothing else changed in it — an `extension-dropped` rule cannot see a slide or a re-spelling elsewhere in the window, so a fill of that shape is only as honest as the surface's `pair` and `secondary_seams` fields.
5. **Test and gate.** Add the rule to `test_checked_in_rules_file_loads` in `rebuild/test_standing_verdicts.py` plus one positive and one negative structural case in the file's idiom; `uv run pytest rebuild/test_standing_verdicts.py -n auto --dist worksteal`, `make prettier`, `uv run pyright`, then `make test-rebuild` detached (`rebuild/` is outside `make test`'s closure, so do not force that gate).
6. **Land it.** Commit in reader terms ("Stop having to verdict …"), then run the cycle detached — `nohup caffeinate -i make review-cycle SERVE=0 > tmp/cycle-pass.log 2>&1 &` — which stops the review server itself because the standing fill writes the store, and when its banner lands restart the server (`nohup uv run python -m rebuild.review.serve > tmp/review-serve.log 2>&1 &`) and confirm with `make verdict-ready`. Report the rule's line from the cycle summary and the census diff the cycle printed.

## What this costs when skipped

Each of these was rediscovered by hand once and is why the probe exists: the same change in a different window carries a different whole-window digest as soon as any other change rides beside it, so an ink-delta family's approvals prove the decision but cannot fill the composed window; the structural extension shape fills blindly past anything that is not a seam, so its dry-run fills must be read, not counted; the rendered fonts position through GPOS, so never reason about a slide from `hmtx` advances — the probe reads shaped placements; a `slide` rule refuses on one stray pixel by design, and a window pairing a blessed slide with a blessed extension drop is the composed reading's case, not a new rule's; and an already-verdicted echo family is evidence for a rule, not a substitute for one — echo only reaches pixel-identical lookalikes, a rule reaches windows the user has never seen.

## Scratch discipline

`tmp/standing-dry.json` and any survey output are scratch and never committed. The durable outcome is the rule, its tests, and the commit message; the fill itself lands through the cycle.
