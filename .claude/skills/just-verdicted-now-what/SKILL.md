The user has just adjudicated units in the review app and wants the new complaints turned into rune changes under `glyph_data/runes/`. The design decisions are the user's, recorded in verdicts and notes. Your job is to get from "18 new complaints" to "the one or two record changes they imply" without re-deriving the repo's invariants. Earlier batches: 94 rejects led to 2 rune changes, and 17 rejects led to 1. If you are proposing more than ≈2 changes per flaw cluster, you have probably mistaken draft targets for fixes.

## Hard rules

- The new complaints are the ones to work on. **Older complaints stay open unless the user asks**, because they are usually tied to an open decision recorded in WHATNEXT.md. Check there before touching one.
- Never write or edit the verdict store or any `verdicts-*.json`, never run `merge_verdicts` while the review server is up, and never rebuild the review corpus (`review.build`). Rebuilding the corpus, the carry, and the merge are `make review-cycle`'s job, which the user runs after the fix is committed.
- Never invent a verdict. A unit without a verdict stays without one, and a skip produces a proposal the user decides on, never a recorded verdict.
- Never author `why:` text. Copy the user's verdict note verbatim (the `note`/`gist` on the reject unit) onto the one record it describes, not onto sibling guard records it does not describe. Unlock records accept `why:` like the policy kinds. If a record shape lacks a `why:` slot, put the verbatim note in a `#` comment on the record instead.
- Never commit without explicit approval. At the natural commit point, spawn a fresh sub-agent for commit-message suggestions that describe the reader's experience, not the mechanism.

## Steps

1. **Write the complaint list.** Run `uv run python rebuild/tools/complaint_list.py` (or `make complaint-list`; it defaults to the live autosave), which writes `tmp/complaints-data.json`. Groups that share provenance pointers (`shares_pointers_with`) are **one flaw that several mechanically drafted targets point at**. The `suggested_records` drafts are grouping keys, not the fix, and a refuse-shaped draft usually only moves the lost join to a different junction. Reduce the groups to flaws before designing anything.
2. **Read the baseline and the units.** The authoritative join map is `rebuild/out/m1/baseline-<config>.subset.tsv.gz`. Grep it for the flaw's codepoint windows across configs. Never decide the scope from reading the FEA, which misses the joins a bare glyph makes through its GPOS anchors alone. The unit JSONs under `rebuild/out/review/units/*.json` hold each window's `before`/`after` renders and an `explain` trace that names the deciding record and every eliminated candidate. Read the explain before reading rune files.
3. **Map every configuration's unit.** The same codepoint window is several units: the ss03-off unit, the ss03 unit, and sometimes an ss10 unit that is in a ledger-ruled class instead. Pull all sibling units and their verdicts from the autosave before designing: **an approved unit must not change unless the new complaint's note explicitly states a pair-wide rule that supersedes it.** Where a fix would also change an approved sibling unit, guard that unit. Refusals and unlocks are pure unions, so a carve-out is expressed by restructuring the refusing record: split the family out of the broad list, and add an `except:`'d record plus `feature:`-scoped records that restore the old behavior under the sets that must not change.
4. **Design the minimal record change.** When a note discusses the distance between two adjacent letters and does not explicitly make that distance depend on farther context or a configuration, focus first on the two letters that bound the space. Treat it as a pair-wide preference and try an `extend` / `contract` on one side of that junction before designing any deeper condition. The complaint list's longer windows are examples of the flaw, not the rule's scope. [How a reject becomes a record](#how-a-reject-becomes-a-record) decides the record's shape. The closed vocabulary is in `doc/rebuild-design.md` §3.3 and §3.4. These details are easy to miss and cost time:
   - `except:` entries are static atoms (family, class, stance, or trait, with **no `joined_at`**), so a "joined at height H" carve-out must be expressed extensionally, by naming the atoms it covers.
   - A `left:` of only `except:` also matches a boundary on the left. A run-splitting token makes the left neighbor a boundary, not the letter before the token.
   - Refuse and require records may not use `right.then`.
   - A stance `order:` breaks ties in join count, and that tie-break often keeps the fourth-letter windows (the ·Tea·Day pair keeping its join, and similar cases) unchanged without any added record.
5. **A/B with probe.** `uv run python rebuild/tools/probe.py E6XX:E6XX:… E6XX:E6XX …` prints the old font's settlement beside the live runes' settlement across every acceptance configuration, one block per window in argument order. Make one call before the edit and one after, each over the whole window list, capture both to files, and diff them. Assert that every guard window is byte-identical and that every intended change is exactly the designed cell swap. Before editing, probe the flaw windows. After editing, probe a set of windows (every rejected window plus the must-not-change neighbors: the bare pair, other left and right families, and boundary tokens on either side) and print only the old-vs-new divergences. Every ss03-off row should show no divergence, and every remaining divergence should be one that already existed and was adjudicated. Confirm that by matching the stored unit's `after` render byte for byte.
6. **Gates.** Run `uv run python -m rebuild.pipeline.run_m1`. Its `--jobs` defaults to the `sweep_job_budget()` width that the artifact cycle already passes, so a bare run sizes itself to the machine. It should report defects 0/0 and the budget not failed, with the boundary and Manual pins passing. The oracle-unmatched delta measures the fix: fixed windows leave the unmatched rows, and intended new divergences join them under existing classes. Then run it with `--conform-only` (the sweep must stay exact; its `--jobs` defaults to the conformance sweep's own `conform_job_budget()`), and run `make test-rebuild`. That is the rebuild suite's self-skipping wrapper: it parses the failure set itself and writes the green record that lets the next `make review-cycle` skip the suite. A hard failure it reports is usually a **content pin** that your change moved as intended; update it by hand and re-run. `make test` self-skips. Run `make prettier` after any Python change.
7. **Commit.** Run `uv run python tools/reflow_yaml.py` on the touched runes (expect a no-op), confirm the spec loads, show the diff, present commit-message candidates, and wait for the go-ahead. After committing, remind the user that the next step is `make review-cycle`. The approved units a fix would likely change (`approved_units_at_risk`) return to the queue, which is expected, not a defect. A unit's id follows its content (`doc/review-cycle.md`), so the carry orphans the verdict of every unit whose outcome the fix changed, and a `u-` id is durable provenance only where a rune's `why:` names it. The carry's `carry counts:` line reports the orphaned verdicts. Account for each one as resolved by the fix or queued to be shown again, and drop none. Don't log the commits in the batch progress file. Git holds them, and that file holds only what is parked, recorded design overrides, the verification recipe, and the resume commands (AGENTS.md's note-taking rules are the authority).

## How a reject becomes a record

- **Revert the authoring decision before adding a counter-record.** When the reviewer rejects the ink itself, not one trigger of it, delete the record that draws it. Don't narrow it or cancel it with another record. Within a migrated alphabet a narrowed record is usually byte-identical to deletion, and it leaves a record that does nothing for the next reader to puzzle over. Cancelling does not work on the entry side at all, because **entry-side `extend` and `contract` do not cancel at name grain**: a `contract:` built to cancel an `extend:` leaves oracle rows unmatched and fires inside windows the reviewer approved.
- **Express a revert as a yielding `prefer`, not a `refuse` and not `mode: absolute`.** Yielding prefers rank after window join count (`doc/rebuild-design.md` §6.1, step 4), so one decides only a tie in join count and leaves every join that wins on join count in place. A `refuse` in the same position removes the join unconditionally and reaches windows the reviewer approved.
- **Scope a same-rune pairing record on `left:`.** A follower-side record does nothing between same-rune neighbors, so the obvious `right:`-only one-liner cannot do the job. It acts through the follower prefer instead and changes unrelated ·X·May·May-shaped windows, approved ones among them. The follower path does not see a `left:` condition that can only match the record's own family, so a pairing record carries one.
- **When the verdicts contradict each other**, with the same cell approved in one window and rejected in another, ask the user instead of editing. A record that satisfies one side undoes a rule the other side depends on.
- **Some rejects have no form in the `when:` vocabulary.** “The predecessor's predecessor is entered” is one: `left:` describes only the immediate predecessor's settled state, and there is no `left2` (`doc/rebuild-design.md` §3.4). A window whose only remaining defect needs such a condition stays documented as one of the remaining rows in its class's `why:` in `rebuild/m1-divergences.yaml` until the vocabulary grows.
- **A record the audit cannot see is not redundant.** The acceptance oracle's windows are at most four letters long, so removing a record whose effect is on longer sequences leaves the divergence audit byte-identical. Never delete a record because removing it and rerunning shows no diff. Work out what it does beyond four letters and pin those windows by hand in `rebuild/test_settle.py` (its ·May-chain pins are the pattern), because no other test checks what settlement chooses there.

## Data shapes

Read these instead of probing the files interactively.

- `tmp/complaints-data.json` is `{manifest_generated_at, verdicts_file, since, totals, groups}`. Each group carries `id`, `kind`, `target` (`{file, keypath}` for a group keyed by a policy draft, `{pointers}` otherwise; a grouping key, not the fix), `pointers` (the provenance records its units share), `classes`, `rejects`/`neithers` (each split `new`/`older`), `approved_units_at_risk` (`{approve, either, identical}` counts of judged units that share the group's pointers), `shares_pointers_with`, and `defer_file`. A complaint entry is `{unit, class, codepoints, notation, verdict, at, note, gist}`. `gist` is the note without its leading provenance markers (`[carried …]` and the other kinds `_MARKER` in `rebuild/tools/verdict_notes.py` lists). The app's group verdict copies one human reject to all of the group's sibling units under one shared `at`, with the typed note only on the unit it was entered on. Treat the group as one flaw with one note.
- `rebuild/out/review/units/` holds each **class** as one JSON file (`<class-id>.json`), or, when the class is larger than one part's byte cap (`SHARD_PART_BYTES` in `rebuild/review/build.py`), as numbered parts (`<class-id>.000.json`, `<class-id>.001.json`, …). Each file is a flat list of unit objects; there are no per-unit files. The fields to read: `codepoints` (colon-separated hex), `configs`, `before` (`{glyphs, junctions}`, old font), `after` (`{cells, junctions, extensions}`, where a cell reads `rune/stance/entry/exit/adjustments`), `explain`, `provenance`, `ink_deltas`, `drafts`. A window's ss10 unit is a separate unit in the ss10 or deferred class files, so a search for sibling units must scan every class file by `codepoints`.
- `verdicts-autosave.json` (repo root) is `{format, manifest_generated_at, exported_at, verdicts}`, and `verdicts` is a **list** of `{unit, verdict, note, at}` records (verdict ∈ approve/reject/either/identical/neither/skip). Key it by `unit` before joining it against units.
